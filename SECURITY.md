# Security policy

## Supported version

Security fixes target the latest released minor version. Pre-release development and beta builds receive fixes on a best-effort basis and should not be used as the stable release.

## Reporting

Do not publish exploit details or sensitive URLs in a normal issue. If you have repository access and private vulnerability reporting is available, use GitHub's security-advisory feature. This repository may be private, so extension users without repository access should use the Contact or Email link on [Cameron Amer's public website](https://www.cameronamer.com/) and identify the message as a Stream Reviver security report.

Start with the affected version, browser, a non-sensitive summary of the issue, expected impact, and whether a malicious page or user interaction is required. Arrange a suitable private channel before sharing sensitive reproduction material. Do not send credentials, private stream URLs, browsing history, or screenshots of private content. A publicly reachable contact link is not evidence that delivery or response time has been tested.

No bug bounty is currently offered. Good-faith reports will be acknowledged and assessed before disclosure. See [docs/SECURITY.md](docs/SECURITY.md) for the threat model and controls.
